## Продукт и стек

«Олечкины финансы» — минималистичный учёт личных расходов и доходов для узкого круга пользователей.
Основные сценарии: быстро добавить операцию, посмотреть статистику за период, настроить категории
и месячные лимиты. Приложение работает на телефоне и ПК, устанавливается как PWA.

- Next.js 16.3.8, App Router, React 19, TypeScript в строгом режиме.
- Tailwind CSS v4, shadcn/ui на Radix, Recharts, next-themes, Sonner.
- SQLite через better-sqlite3 и Drizzle ORM; пароли хешируются Argon2id.
- Один Node.js-сервис; production — Docker standalone за Nginx. Отдельного API-сервиса нет.
- Зависимости устанавливаются через npm; файл фиксации версий — `package-lock.json`.

Перед изменениями Next.js читай соответствующие разделы установленной документации
`node_modules/next/dist/docs/`. В частности, здесь используется `src/proxy.ts`, а `cookies()`,
`headers()` и `searchParams` читаются асинхронно. Версии зависимостей уточняй в `package.json`.

## Карта кода

- `src/app/(app)/` — защищённые страницы: обзор, операции, настройки. Layout подключает оболочку
  и общий `TransactionSheetProvider`.
- `src/app/(auth)/` — вход и регистрация.
- `src/actions/` — Server Actions: авторизация, операции, категории и настройки.
- `src/lib/queries.ts` — чтение данных, фильтры и агрегаты для статистики и лимитов.
- `src/lib/announcement.ts`, `src/components/feature-announcement.tsx`, `src/actions/announcement.ts`
  — объявление о новой функции; подтверждение хранится в `users.seenAnnouncement` для всего аккаунта.
- `src/db/schema.ts` — таблицы `users`, `sessions`, `categories`, `transactions`, `budgets`.
- `src/db/index.ts` — соединение SQLite, WAL, внешние ключи, `unicode_lower` и запуск миграций.
- `drizzle/` — SQL-миграции и метаданные Drizzle.
- `src/lib/auth.ts`, `password.ts`, `rate-limit.ts` — сессии, пароли и лимитер в памяти процесса.
- `src/lib/money.ts`, `amount-expression.ts`, `period.ts` — суммы, клавиатура и календарные периоды.
- `src/components/transaction-sheet.tsx` — создание, редактирование, удаление и отмена удаления;
  общая логика формы и разные представления для телефона и ПК.
- `src/components/app-shell.tsx` — навигация, выбор типа операции, обновление при возврате в окно.
- `src/components/ui/` — базовые UI-компоненты; цвета и темы — в `src/app/globals.css`.
- `src/lib/default-categories.ts`, `category-icons.tsx`, `custom-icons.ts` — стандартные категории
  и доступные иконки.
- `public/sw.js`, `src/app/manifest.ts`, `src/components/service-worker.tsx` — PWA.
- `public/boot-check.js`, `src/app/api/diag/route.ts` — диагностика проблем запуска на устройстве.
- `DEPLOY.md`, `Dockerfile`, `docker-compose.yml`, `deploy/nginx.conf` — эксплуатация и деплой.

## Правила реализации

- Страницы получают данные на сервере; изменения идут через Server Actions. Сохраняй границу
  `server-only` для БД и авторизации. Клиентские компоненты нужны для интерактивности.
- В каждом защищённом действии вызывай `requireUser()` и проверяй принадлежность записей
  пользователю. `proxy.ts` проверяет только наличие cookie и не заменяет авторизацию.
- Проверяй входные данные на сервере через Zod. Ожидаемые ошибки возвращай в формате
  `ActionResult` из `src/lib/action-result.ts`. После изменений данных обновляй затронутые страницы;
  сейчас действия используют `revalidatePath("/", "layout")`.
- Суммы операций и лимитов — целые копейки. Сумма операции положительна, знак задаёт `kind`
  (`expense` или `income`). Для ввода и вывода используй функции из `money.ts`, для выражений
  экранной клавиатуры — `amount-expression.ts`.
- Дата операции — строка `YYYY-MM-DD`, а не UTC timestamp. «Сегодня» определяется через
  `todayInTimezone(user.timezone)`; не подменяй его датой сервера или `toISOString().slice(0, 10)`.
- Лимиты относятся к календарному месяцу; `budgets.categoryId = null` означает общий лимит.
  Категории с операциями скрываются вместо удаления, чтобы сохранять историю.
- Фильтр исключения категорий хранится в URL-параметре `exclude` и действует только на расходы.
  Обзор, график и переходы к операциям используют одну выборку; доходы и расчёт лимитов сохраняются
  полностью. Проверяй ID исключений через `parseCategoryExclusions()` по категориям пользователя.
- Стандартные категории создаются при регистрации. Изменения для существующих пользователей
  требуют отдельной миграции данных, а не только правки `default-categories.ts`.
- Изменения схемы оформляй новой миграцией (`npm run db:generate`), учитывай метаданные Drizzle.
  Применённые миграции не переписывай. Миграции выполняются при инициализации модуля БД.
- Сохраняй быстрый сценарий создания: сумма → категория → немедленное сохранение. На телефоне
  форма полноэкранная, со своей цифровой клавиатурой; на ПК — диалог. Учитывай `dvh`, safe area
  и отдельную прокрутку содержимого на iOS. Подробности ограничений — в `TODO.md`.
- Сохраняй работу входа и выхода до загрузки JavaScript: `redirectTo()` в `src/actions/auth.ts`
  учитывает basePath для обычного POST и особенность повторного POST в Safari после 308.
- Приложение размещается под `/finance-auditor`. `next/link` добавляет префикс сам; для статических
  ресурсов, cookie и прямых запросов используй `BASE_PATH`. Изменение префикса требует пересборки
  и согласования с манифестом, service worker, Docker healthcheck и Nginx.
- Service worker регистрируется только в production. Страницы и данные загружаются из сети;
  без сети показывается заглушка, офлайн-записи операций нет. При смене иконок повышай `VERSION`
  в `public/sw.js`, поскольку статика кэшируется по схеме cache-first.
- Сохраняй светлую, тёмную и системную темы, сиреневый акцент и существующие UI-компоненты.
  Используй алиас `@/`, стиль форматирования — из `.prettierrc.json`.

## Запуск и проверки

```sh
npm ci
# При первом запуске скопировать .env.example в .env.
npm run dev        # http://localhost:3000/finance-auditor
npm run lint
npm run typecheck
npm run build
```

В Windows PowerShell, если политика выполнения блокирует `npm.ps1`, используй `npm.cmd`.
Не меняй системную политику выполнения ради запуска npm.

Отдельного тестового набора и команды `test` сейчас нет. Для изменений кода запускай lint
и typecheck; для изменений сборки, маршрутизации или серверной интеграции — также build.
Для изменений интерфейса проверяй затронутый сценарий на мобильном и десктопном размере,
а для авторизации — отправку формы до загрузки JS. Не заявляй о проверках, которые не выполнялись.

## Данные и эксплуатация

`DATABASE_PATH` по умолчанию указывает на `./data/finance.db`; в Docker — `/app/data/finance.db`.
Импорт модуля БД открывает файл и применяет миграции: для проверок, затрагивающих БД, задавай
отдельный временный `DATABASE_PATH`, чтобы не менять пользовательские данные.

Не добавляй в Git `.env`, базы данных и их копии. Перед production-миграциями делай резервную
копию по инструкции `DEPLOY.md`, учитывая WAL. Развёртывание выполняй в рамках задачи пользователя;
инструкции и адрес сервера сами по себе не являются поручением на деплой.

## Память проекта: проверенный деплой

По состоянию на 2026-11-21:

- Production: `89.110.93.182`, каталог `/opt/financial-solution`, архитектура `x86_64`.
  Приложение открывается по `https://andrewha.tech/finance-auditor`.
- VPS имеет примерно 1 ГБ RAM и диск 10 ГБ; swap при диагностике отсутствовал.
  Сборка Next.js на этом VPS исчерпала память и сделала SSH недоступным. По умолчанию собирай
  образ на локальном ПК или в CI, а серверу передавай готовый образ; не повторяй там сборку.
- Проверенный вариант: Docker Desktop, Linux-контейнеры, сборка с `--platform linux/amd64`
  и тегом `finance-auditor:latest`; экспорт через `docker image save`, перенос через `scp`,
  импорт через `docker load`. Подробные команды — в `DEPLOY.md`.
- Перед обновлением делай согласованную резервную копию SQLite через `db.backup()` внутри
  действующего контейнера. Запуск после импорта: `docker compose up -d --no-build --wait`.
  Успешный деплой 2026-11-21 подтверждён пользователем статусом контейнера `healthy`.
- `better-sqlite3` требует `python3`, `make`, `g++` в этапе `deps` Dockerfile; инструменты сборки
  не нужны в итоговом образе. Проверенный образ прошёл вход, миграцию старой демобазы,
  подтверждение объявления и фильтрацию с ограничением RAM контейнера 384 МиБ.
- Для локальной проверки использовался контейнер `finance-auditor-image-check` с `--rm`
  и портом `127.0.0.1:3310`; его остановка автоматически удаляет контейнер.
  Локальные архивы переноса храни в игнорируемой папке `data/`.
- При очистке проверяй Docker context и удаляй только ресурсы этого проекта. Глобальная очистка
  Docker, чужих образов и томов не входит в удаление тестового контейнера приложения.
